1. The direction, in one paragraph

Calm clinical, not administrative. Soft white surfaces on a faintly green canvas, generous rounding, plain sentences, one obvious action per screen. An earlier draft used a dense high-contrast internal-tool aesthetic; it was accurate about the audience and wrong about the experience. Five people using this occasionally need it legible on a bad day, not efficient on a good one.

Two rules hold the whole thing together:

Colour that is not the accent means something. Status and environment own every other hue on screen. Nothing is coloured to look designed.

No shadows anywhere. Depth comes from the tonal step between white bands and the canvas. A shadow added later matches nothing.

3.2 Environment

The chip always renders, production included.
Decision Production is the most heavily marked state, not the unmarked one
Rejected Hiding the chip in production, per P-03.4
Reason Absence-as-a-value is the failure mode P-02.2 rejects for the organization id — a platform context carries no organization as a distinct kind, not as a null. A missing chip and a broken chip look identical, and the default state of every misconfiguration is a header that looks like production. The risk is one-sided: a mistake on staging costs nothing, a mistake on production creates a practice with real rows in it
Decision Only staging and production also carry the 3px top edge
Rejected The edge on all four, or none
Reason The edge is for the two environments that look real. Local and development announce themselves through the data in them

Colour is never the only carrier. The chip names the environment in words; colour and the dot are the second and third channels.

The value is a union of the four names from environment.ts. Not a string, not a boolean isProduction. An unreadable value renders production treatment and reads Unknown — matching LLD.md §3, an unresolvable state is treated as the most dangerous one.

The environment appears in the browser tab. <page> · EPM Platform · <Environment>.

Title h1, 18px/600. Exactly one per page

Action At most one, right-aligned

3.4 The add button

Solid accent pill with an inset white circular tile carrying the plus.

The plus is the medical cross doing double duty — it is both "add" and the mark of the domain. That is why it is drawn as a deliberate object in a tile rather than a thin icon floating beside the label, and why a building glyph was rejected: the label already names the noun, so a building icon would carry no information.
Decision Pill radius is reserved for status pills and the single primary action per screen
Rejected Pills everywhere, or 8px on the primary action
Reason The shape itself then signals "this is the main thing", and a second pill-shaped button on a screen is a design error anyone can spot

The tile is decorative. aria-hidden="true"; the label is the accessible name. It must never collapse to icon-only — 1024px is the floor and there is room.

One field takes everything. Typing a name, a plan, or a status all go into the same input.

Result count Right-aligned inside the field, 11px --epm-ink-3, <matched> of <total>

Decision A single field that parses into q, status and plan
Rejected A field plus status chips; a field with attached dropdowns; status counts beside a small search
Reason Chosen in review. It is the smallest and most flexible panel, and it is the one that still works at four hundred practices

6.1 The risk, and how it is contained

The server takes q, status and plan as separate parameters. One field means the client guesses which is which, and a wrong guess is silent. These rules make the guess deterministic and visible. They are not optional.

Parsing. Split the input on whitespace. Match each token, case-insensitively, against a closed vocabulary:

Vocabulary Terms
Status active, trial, read-only, readonly
Plan basic, standard, pro

A token matching exactly one term becomes that filter. Every remaining token joins with spaces to form q.

The interpretation is always visible. A token consumed as a filter renders as a small removable pill inside the field, ahead of the free text. The user always sees what the field decided. A guess the user cannot see is the defect this design has to avoid, and the pill is the whole mitigation.

Quoted text is never a filter. "basic" in quotes always goes to q. This is the escape hatch for a practice actually named Basic Care — otherwise its own name filters it out of its own search.

One of each, at most. A second status token is treated as free text, not as a second filter. Same for plan.

Ambiguity is never resolved by guessing. A token matching both vocabularies goes to q.

The URL is the state. q, status and plan are query parameters. Results are shareable and the back button works. Debounce input by 300ms before navigating.

No results names what was searched and offers one control to clear it. It never says Nothing here.

6.2 What this needs from the backend

The result count reads <matched> of <total>, so the response needs the unfiltered total alongside the filtered one. The proposed shape in MILESTONE-F1-PLATFORM.md §5 returns total only, which is the filtered count. This is a change to the proposed contract and must be settled when the route is signed off — not discovered during implementation.

7. Accessibility floor

Done when items, not aspirations.
Skip link First focusable element, visible on focus, targets the content landmark
Landmarks header and main. There is no nav — there is no navigation
Focus on navigation Angular's router does not move focus. The layout moves it to the h1 on every completed navigation
Focus visibility 2px accent outline at 2px offset. outline: none without a replacement fails lint
Contrast 4.5:1 for text, 3:1 for every status edge, chip border and meter. Check all five environment chips and all three status treatments — the soft tints are the risk in this palette
Reduced motion prefers-reduced-motion: reduce removes all transitions. Nothing moves beyond 120ms colour changes
Search field A real <input type="search"> with a label. The filter pills inside it are removable by keyboard and announce their removal
Icon-only elements None. Every control has a visible text label
