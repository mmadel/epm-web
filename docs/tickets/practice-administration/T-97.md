## 2. Goal

An org admin opens the staff console in a browser, can see they are in the staff console, and can
move between its four sections — each of which renders its own component at its own URL.

---

## 3. Scope

### In

- The `staff` app shell: header, navigation, content outlet
- The route table: a landing redirect, four section routes, an unknown-route screen
- Four section components, each at its own route, each lazily loaded
- The navigation menu: four items, active state, direction-aware layout
- Enough visual identity that the console is recognisably the staff console and not the platform one
- `--epm-accent` consumed from `ui`, with the `staff` value set

### Out

- **Role-based navigation.** Every item is visible to every signed-in caller in this ticket. Hiding an item needs the session from `core` — `T-81`, `M2`. Raise a ticket; do not build a half version reading roles from somewhere else
- Any real content inside the four sections — `T-65`, `T-66`, `T-67`, `T-69`
- Any call to `api-client`. The shell calls nothing
- The branch chooser — `T-82`, `M2`
- Sign-in, the 401 path, the not-writable banner — `T-80`, `T-83`, `T-69`
- Message wording in either language

## 4. Contract

**Backend.** `None.` No route added, none changed. **This ticket makes no HTTP call at all.**

### Routes

| Path            | Renders                                    | Loaded | Owner ticket |
| --------------- | ------------------------------------------ | ------ | ------------ |
| `/`             | Redirects to `/practice`                   | —      | This ticket  |
| `/practice`     | Practice details section                   | Lazily | `T-65`       |
| `/clinics`      | Branches section                           | Lazily | `T-66`       |
| `/staff`        | Staff section                              | Lazily | `T-67`       |
| `/subscription` | Subscription section                       | Lazily | `T-69`       |
| Anything else   | Unknown-route screen, **inside the shell** | —      | This ticket  |

**Each section is one component with a placeholder body**, at its own URL, reachable by typing it.
The owning ticket replaces the body and touches neither the route nor the nav.

**An unknown route renders inside the shell, never as a bare page.** The navigation stays usable —
a dead end with no way out is how a user reloads the app to escape it.

**No practice id appears in any path** (`LLD-PRACTICE.md` §1). The practice comes from the caller.
A route segment for it would be a way to ask for another practice.

### The shell

| Region     | Holds                                                                                              |
| ---------- | -------------------------------------------------------------------------------------------------- |
| Header     | The wordmark, which is also the link to `/practice`. The signed-in person's name once `T-81` lands |
| Navigation | Four items, in the order above                                                                     |
| Content    | The routed outlet                                                                                  |

**The console must be identifiable at a glance.** A person may hold accounts in both consoles, and
the two have opposite tenancy rules — one runs with the tenant filter off. The wordmark and the
accent are what separate them.

|                | `staff` app                           | `platform` app        |
| -------------- | ------------------------------------- | --------------------- |
| `--epm-accent` | **Set by this ticket.** Not `#0E7C66` | `#0E7C66`             |
| Nav band       | Four items                            | None — wordmark only  |
| API base       | `/api/v1/**`                          | `/api/v1/platform/**` |
| Keycloak realm | `epm-staff`                           | `epm-platform`        |

**A platform admin cannot reach this shell.** Separate application, separate realm, no shared route.
Structural, not a guard.

### States

| State             | Trigger                   | What is shown                                                            |
| ----------------- | ------------------------- | ------------------------------------------------------------------------ |
| Nav item active   | The route matches         | The accent marks it. Not colour alone — a shape or weight change as well |
| Section loading   | A lazy chunk is in flight | A placeholder in the content region. The shell and nav stay rendered     |
| Unknown route     | No route matches          | The unknown-route screen inside the shell                                |
| Direction flipped | Locale is Arabic          | Same layout, mirrored. No rule uses `left` or `right`                    |

**The shell never blanks while a section loads.** Replacing the whole page on a lazy load makes a
route change look like a reload.

### Library placement

| Piece                                                     | Library                                                |
| --------------------------------------------------------- | ------------------------------------------------------ |
| Shell, routes, nav container, the four section components | `staff`                                                |
| Nav item, header, placeholder, layout primitives          | `ui`                                                   |
| Nothing                                                   | `core` — this ticket reads no session and calls no API |

**`ui` must not import `api-client`.** Not exercised here because the shell calls nothing, but the
boundary is stated so the four owning tickets inherit it. Nothing enforces it today — §10.

## 7. Acceptance criteria

1. Given a browser at `/`, when the app loads, then it redirects to `/practice`.
2. Given the shell renders, then the wordmark identifies the staff console and links to `/practice`.
3. Given each of `/practice`, `/clinics`, `/staff`, `/subscription` typed directly, then that section's component renders inside the shell.
4. Given each section route, then its component is loaded lazily — a separate chunk in the build output.
5. Given a nav item is clicked, then the URL changes and the content region swaps without a full page load.
6. Given a route matches, then exactly one nav item is marked active.
7. Given a nav item is active, then it is distinguished by more than colour.
8. Given `/nonsense`, then the unknown-route screen renders inside the shell with the nav still usable.
9. Given a lazy chunk in flight, then the shell and nav stay rendered and a placeholder occupies the content region.
10. Given the locale is Arabic, then the layout mirrors and no stylesheet rule in this ticket uses `left` or `right`.
11. `--epm-accent` is set for the `staff` app and is not `#0E7C66`.
12. No component added by this ticket imports `api-client`, and no HTTP request is made on load.
13. No route path contains a practice id or any tenant identifier.
14. `ng build` and `ng test` are green.

## 11. Sub-tasks

Three, lettered, in order. `WORKFLOW.md`: **sub-tasks share the ticket's branch**, one commit each,
all in one pull request, and **the order is the order**.

There is no `feature/T-97a-...`. Everything lands on `feature/T-97-practice-admin-shell`.

|       | Deliverable                                                                                                                                                                                                                                  | Satisfies           | Commit                                                             |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------- | ------------------------------------------------------------------ |
| **a** | **The route, and knowing where you are.** The `staff` app boots at `/`, redirects to `/practice`, and renders a shell with the wordmark and the accent set. One placeholder in the content region. An unknown route renders inside the shell | 1, 2, 8, 11, 12, 13 | `T-97a: boot the staff shell at its own route with the accent set` |
| **b** | **The navigation.** Four items in order, active state derived from the route, distinguished by more than colour, direction-aware. Still one placeholder behind them                                                                          | 6, 7, 10            | `T-97b: add the four-item nav with a route-derived active state`   |
| **c** | **A component and a sub-route per item.** Four lazily loaded section components, each at its own URL, each with a placeholder body naming the ticket that will fill it                                                                       | 3, 4, 5, 9          | `T-97c: give each nav item its own lazy route and component`       |

### Why this order

**`a` before `b`.** A nav item's active state is derived from the router. With no router there is
nothing to derive it from, and the state gets held in a variable that then has to be removed.

**`b` before `c`.** The nav is what proves the routes are reachable by clicking as well as by typing.
Building four routes first and the nav after means testing them by URL only, which is not how anyone
uses the app.

**`c` last, and it is the one that carries the risk.** Lazy loading is the criterion a passing test
suite hides — eager imports render every route correctly and produce one bundle. Assert the chunks.

### What is not a sub-task

| Not                                     | Why                                                                                                  |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Hiding a nav item by role               | Needs the session — `T-81`, `M2`. A version reading roles from elsewhere is a second source of truth |
| Any section's real content              | `T-65`, `T-66`, `T-67`, `T-69` — one owner each                                                      |
| The `ui`-imports-`api-client` lint rule | A separate concern across the whole workspace, not this shell                                        |
