## 4. Contract

**Frontend — the control.**

|       |                                                        |
| ----- | ------------------------------------------------------ |
| Where | Inside `projects/staff/src/app/sections/staff-section` |
| Calls | `replaceStaffRoles`                                    |
| Who   | Org admin. The control is not rendered for anyone else |

### The control

**Checkboxes over the full set, pre-ticked** — `DOCTOR`, `RECEPTIONIST`, `ORG_ADMIN`
(`LLD-PRACTICE.md` §2.4).

**Not** a list with add and remove buttons. The call replaces the whole set, and a control shaped for
incremental edits invites thinking the API does not support.

| Label | Control                          | Required | Validation          | On failure                                          |
| ----- | -------------------------------- | -------- | ------------------- | --------------------------------------------------- |
| Roles | checkbox group over the full set | yes, ≥1  | At least one ticked | `roles.atLeastOne` beneath the group; save disabled |

### States

| State      | Trigger                               | Renders                                                             |
| ---------- | ------------------------------------- | ------------------------------------------------------------------- |
| Ready      | The person's current set, pre-ticked  | The three checkboxes                                                |
| Unchanged  | The ticked set equals the current set | **Save disabled**                                                   |
| Saving     | `replaceStaffRoles` in flight         | The group and save disabled                                         |
| Saved      | 200                                   | The resulting set from the **response**, not the ticked state       |
| Last admin | 422 `EPM-ORG-010`                     | Message beneath the group; **the ticks revert to the server's set** |
| Not found  | 404                                   | The staff list refetches                                            |
| Error      | Any other failure                     | `ErrorMessage`                                                      |

**Language and direction:** both languages, direction-aware.

---

## 5. Logic

**Frontend.**

**The whole set is sent on every save**, never a difference. `PUT`, not `PATCH`.

**On success the rendered set comes from the response**, not from what was ticked. The two agree today;
reading the response means they still agree if a rule ever normalises the set.

**On `EPM-ORG-010` the ticks revert to the server's set.** Leaving the failed ticks on screen shows a state
that does not exist, and the next save would send it again.

**The last-admin rule is never evaluated client-side.** The client does not know how many active org
admins the practice has, and computing it from a list is the same defect as a threshold in a chart
component (`LLD.md` §12). **Disabling the checkbox to prevent the error is wrong** — the server owns the
rule.

**An unknown role value never reaches the wire.** The checkboxes are the full fixed set, so
`EPM-REQ-002` is unreachable from this control — it is mapped anyway, because a generated client can
outlive a hand-written assumption.

**After success the staff list refetches**, so the roles column and any dependent rendering move together.

## 7. Acceptance criteria

1. Given a staff member holding `DOCTOR`, then `DOCTOR` is ticked and the other two are not.
2. Given the ticked set equals the current set, then save is disabled.
3. Given a tick changes, then save is enabled.
4. Given all three unticked, then save is disabled and `roles.atLeastOne` renders.
5. Given save, then `replaceStaffRoles` is called once with the **whole** set.
6. Given a save in flight, then the group and save are disabled and re-clicking sends nothing.
7. Given 200, then the rendered set comes from the response.
8. Given 200, then the staff list refetches.
9. Given 422 `EPM-ORG-010`, then a message renders and **the ticks revert to the server's set**.
10. Given 422 `EPM-ORG-010`, then the last remaining `ORG_ADMIN` checkbox was **not** disabled beforehand — the rule is the server's.
11. Given 404, then the staff list refetches.
12. Given an unknown error code, then a generic message renders and the code is logged.
13. Given a doctor or receptionist, then the control is not rendered.
14. Given the control, then it is checkboxes over the full set, not an add-and-remove list.
15. Given Arabic, then the layout mirrors with no `left`/`right` in its styles.
16. Given every new colour pair, then it is in `contrast.test.js` and passes.
17. Given no request from this control, then none carries an `org_id`.
18. `npm run build` and `ng test` green.

### Why this order

**`d` before `e`** — unusually. The revert-on-422 behaviour is the ticket's real content, and wiring the
control into the screen before it exists means the first thing a reviewer sees is the version that leaves
a false state on screen.

**`e` is where anything is demonstrable**, and it is also where the read-only rendering must be **deleted**
rather than left beside the new control.

_Rejected: data, component, adoption, then validation and errors._
