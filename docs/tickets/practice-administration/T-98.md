# T-98 — One `PageHeader` in `ui`

## 1. Header

|         |                                        |
| ------- | -------------------------------------- |
| Release | `M3`                                   |
| Cat     | FE                                     |
| Area    | Shell                                  |
| Needs   | —                                      |
| Days    | 1                                      |
| Branch  | `feature/T-98-page-header`             |
| Design  | `T-97`'s shell decisions; `LLD.md` §12 |

**No `Status` row.** Status lives in `BOARD.md` (`WORKFLOW.md`).

**This blocks `T-65`, `T-66`, `T-67` and `T-69`.** Every section needs a title, a supporting line and one
action. Without this, four tickets invent four layouts and there is no obvious one to standardise on
afterwards. **It is one day and it must land first.**

**Extract, do not write fresh.** `platform`'s console already has a good header. It lives in `platform`,
which is why it cannot be used — the job is moving it into `ui`.

---

## 2. Goal

Every section of the staff console opens with the same header, and no section author decides what a
header looks like.

---

## 3. Scope

### In

- `PageHeader` in `projects/ui/src/lib/`, exported from the library's public surface
- Title, supporting line, and a single projected action slot
- `platform`'s console moved onto it, so one implementation exists rather than two
- Its colour pairs added to `tools/design-tokens/contrast.test.js`
- A spec holding it to its behaviour

### Out

- **Any section body.** `T-65`–`T-69` own those
- Breadcrumbs, tabs, or a second action slot. Nothing in `M3` needs them — §10
- The pulse glyph — `T-100`
- Navigation — `T-101`

---

## 4. Contract

**Frontend — the component.**

|             |                                                                 |
| ----------- | --------------------------------------------------------------- |
| Selector    | `lib-page-header`                                               |
| Location    | `projects/ui/src/lib/page-header/`                              |
| Imported by | `staff` sections and `platform`. **Never imports `api-client`** |

| Input        | Type   | Required | Notes                                                                  |
| ------------ | ------ | -------- | ---------------------------------------------------------------------- |
| `title`      | string | yes      | Already translated by the caller. **The component does not translate** |
| `supporting` | string | no       | One line. Absent renders nothing, not an empty block                   |

| Slot       | Notes                                                                                     |
| ---------- | ----------------------------------------------------------------------------------------- |
| `[action]` | **One** projected action. Two is `T-65`'s problem to avoid, not this component's to allow |

**States:** a title alone; a title with a supporting line; a title with an action; all three. **Four
states, each with a spec.**

**Language and direction:** direction-aware. Logical properties only — no `left` or `right`. The action
sits at the inline end in both directions.

**No route.** It is a component, not a screen.

---

## 5. Logic

**Frontend.** No derived values, no state, no fetching. It is presentational.

**The caller passes translated strings.** Putting `TranslatePipe` inside would make every consumer's key
namespace this component's business.

**Nothing is computed here.** A header that decided its own title from a route would tie `ui` to the
router.

---

## 6. Data

`No table created, altered or dropped. No migration.` No server call.

---

## 7. Acceptance criteria

1. Given `title` only, then the title renders and no supporting element is in the DOM.
2. Given `title` and `supporting`, then both render.
3. Given a projected action, then it renders at the inline end.
4. Given no projected action, then no empty action container is in the DOM.
5. Given `dir="rtl"`, then the action sits at the inline end without a mirrored stylesheet.
6. Given the stylesheet, then it contains no `left`, no `right`, and no raw hex outside `_tokens.scss`.
7. Given every colour pair the component introduces, then each appears in `tools/design-tokens/contrast.test.js` and passes.
8. Given `platform`'s console, then it renders through `lib-page-header` and its own header implementation is gone.
9. Given `ui`, then it does not import `api-client` as a value.
10. `npm run build` and `ng test` green.

---

## 8. Tests

| Kind         | Spec                                   | What it proves | Fails without the change                                             |
| ------------ | -------------------------------------- | -------------- | -------------------------------------------------------------------- |
| Component    | `page-header.spec.ts`                  | Criteria 1–5   | The component does not exist                                         |
| Design       | `tools/design-tokens/contrast.test.js` | Criterion 7    | A new colour pair with no entry passes every other check             |

**Criterion 4 is the one a green suite hides.** An always-rendered empty container passes every visual
check and pushes the title off its baseline in three of the four states.

## 10. Stop and report

| Situation                                                       | Do not                                                                                                                          |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **A section wants two actions**                                 | Add a second slot. One action was the shape agreed; a second slot means every section decides its own hierarchy again. Raise it |
| Breadcrumbs or tabs look obviously needed                       | Add them. Nothing in `M3` uses them                                                                                             |
| Translating inside the component looks tidier                   | Move `TranslatePipe` in. It makes every consumer's key namespace this component's business                                      |
| **`platform`'s header carries the pulse glyph**                 | Move the glyph as part of this. That is `T-100` — sequence it after, or the two tickets edit the same file                      |
| A new colour is needed and adding it to the contrast test fails | Ship the colour. The contrast test is build-failing by design                                                                   |

## 11. Sub-tasks

Four, lettered, in order. Sub-tasks share the ticket's branch, **one commit each**, all in one pull
request, and **the order is the order.** There is no `feature/T-98a-...`.

**The `a`–`f` layer shape does not apply.** There is no data layer, no route and no error path — this is
one presentational component, so the letters follow the artefact.

|       | Layer     | Deliverable                                                                                           | Tests in the same commit                    | Proves                                            |
| ----- | --------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------- | ------------------------------------------------- |
| **a** | Component | The component, its inputs, its slot, its four states                                                  | `page-header.spec.ts`                       | Criteria 1–5                                      |
| **b** | Tokens    | The stylesheet in colour tokens and logical properties, and every new pair added to the contrast test | `contrast.test.js`                          | Criteria 6, 7                                     |
| **c** | Adoption  | `platform` moved onto it, its own header deleted                                                      | Manual render, recorded in the pull request | Criterion 8                                       |
| **d** | Export    | Added to `ui`'s public surface                                                                        | Existing `ui` import test                   | Criterion 9, and that `T-65`–`T-69` can import it |

### Why this order

**`a` before `b`**, because the token set is decided by what the component actually renders.

**`c` before `d`.** Moving `platform` first proves the component is general rather than shaped for one
consumer. Exporting it before that invites four sections to adopt something only ever tested against one.

### What is not a sub-task

| Not                  | Why                                  |
| -------------------- | ------------------------------------ |
| Any section body     | `T-65`–`T-69`                        |
| The pulse glyph      | `T-100`                              |
| A second action slot | Raised in §10 — a decision, not work |

### The risk this shape carries

**Small, but it gates four tickets.** If `c` reveals `platform`'s header needs something the four sections
do not, **stop and report rather than adding an input for each** — a component with six optional inputs
standardises nothing.
