## 4. Contract

**Frontend — the screen.**

| Component | `projects/staff/src/app/sections/practice-section.ts`                                         |

### Calls

| Purpose              | `operationId`        | Who can call it                    |
| -------------------- | -------------------- | ---------------------------------- |
| Name, status, counts | `getOrganization`    | Any staff member                   |
| Seat counter         | `getSubscription`    | **Org admin only** — 403 otherwise |
| Save the name        | `updateOrganization` | Org admin — 403 otherwise          |

### Fields

| Label         | Control | Required | Validation | On failure                                 |
| ------------- | ------- | -------- | ---------- | ------------------------------------------ |
| Practice name | text    | yes      | Non-blank  | `practice.name.required` beneath the field |

**Read-only, not fields:** status, branch count, staff count, plan, seat limit, seats used.

### States

| State                | Trigger                        | Renders                                                                           |
| -------------------- | ------------------------------ | --------------------------------------------------------------------------------- |
| Loading              | Either resource in flight      | Skeleton in the header and the counter                                            |
| Ready                | Both resolved                  | The form and the counter                                                          |
| **Counter withheld** | `getSubscription` returns 403  | The screen renders without the counter. **Not an error** — §10 item 2             |
| Saving               | `updateOrganization` in flight | **Save disabled**, form disabled                                                  |
| Saved                | 200                            | The new name, Save enabled and unchanged-disabled                                 |
| Field error          | 400 `EPM-REQ-001`              | Message beneath the named field                                                   |
| Rule error           | 422 `EPM-ORG-007`              | Message through `ErrorMessage`                                                    |
| Forbidden            | 403 on save                    | **Deferred** — the form renders for everyone until the session carries a role. §5 |
| Error                | Either read fails              | `ErrorMessage`, with a retry                                                      |

**Language and direction:** both languages, direction-aware. Logical properties only.

## 5. Logic

**Frontend.**

**Server data comes through the resource API and is held in signals** (`LLD.md` §12). No state library.

**The seat counter is not computed here.** `seatsUsed` and `seatLimit` come from `getSubscription`. **A
count derived client-side from a staff list is the same defect as a threshold in a chart component.**

**Save is disabled while the request is in flight, and while the name is unchanged.**

**Hiding the form from a non-admin is presentation, not security.** The server refuses the request
regardless (`LLD.md` §12). The form is hidden because showing a control that always 403s is a worse
screen, not because hiding protects anything.

**And it is deferred, because there is nothing to read it from.** `core`'s `Session` is a two-arm union
— `platformAdmin` and `organizationMember` — and neither arm carries a role. The staff console provides
no session source at all. Until one does, this screen renders the form for every staff member and a
doctor who saves is refused by the server with the 403 handled as an error like any other.

**That costs criterion 5 and nothing else** (§7). It is worth being exact about why, because the
neighbouring criterion looks like it should fall with it and does not: **criterion 4 is reactive**. The
403 on `getSubscription` arrives from the server and the data layer turns it into a state, so the
counter is withheld correctly without anything knowing who the caller is beforehand. Only criterion 5
needs the answer **before** a call is made, which is the one thing a session provides and a response
cannot.

The deferral is a worse screen, not a hole: showing a control that always 403s is exactly what the
paragraph above calls out, and the server still refuses. When the role lands, sub-task `b` gains one
`@if` and the criterion is met — no data layer changes.

**No error code is rendered raw.** `ErrorMessage` turns a code into a message in the user's language, and
an unknown code renders a generic message rather than a blank screen (`LLD.md` §7).

**No `org_id` is sent, ever.** There is nowhere for the server to accept one.

## 7. Acceptance criteria

1. Given the route is visited, then `getOrganization` is called once and the name, status and counts render.
2. Given both resources in flight, then a skeleton renders and no control is interactive.
3. Given an org admin, then the seat counter renders `seatsUsed` and `seatLimit` from `getSubscription`.
4. Given a doctor, when `getSubscription` returns 403, then the screen renders **without the counter and without an error**.
5. ~~Given a doctor, then the name form is not rendered.~~ **Deferred — not in this ticket's scope, and
   not a criterion this ticket is reviewed against.** The session carries no role and the staff console
   provides no session source, so there is nothing to gate on; see §5. Met by a later ticket, which adds
   the `@if` and this spec. Until then the form renders for every staff member.
6. Given an org admin edits the name and saves, then `updateOrganization` is called once and the new name renders.
7. Given a save in flight, then **Save is disabled** and re-clicking sends nothing.
8. Given the name is unchanged, then Save is disabled.
9. Given 400 `EPM-REQ-001`, then the message renders beneath the named field.
10. Given 422 `EPM-ORG-007`, then a message renders through `ErrorMessage`.
11. Given an unknown error code, then a generic message renders in the user's language and the code is logged.
12. Given `getOrganization` fails, then `ErrorMessage` renders with a retry that re-issues the call.
13. Given Arabic, then the layout mirrors with no second stylesheet and no `left`/`right` in the section's styles.
14. Given the section's styles, then no raw hex appears outside `_tokens.scss`.
15. Given every new colour pair, then it appears in `tools/design-tokens/contrast.test.js` and passes.
16. Given the built bundle, then `practice-section` is **not** in the initial chunk.
17. Given `ui`, then it does not import `api-client` as a value — the call sits in a `staff` container.
18. Given no request from this screen, then none carries an `org_id`.
19. `npm run build` and `ng test` green.

standing between a doctor and a broken screen. Nothing distinguishes the two audiences up front any
more, so the 403 is the first and last moment the console finds out — and a spec that only ever mocks a
200 never takes that path. The screen would then ship showing an error to every doctor who opens it,
with the suite green. **The 403 fixture is not optional.**

## 11. Sub-tasks

Six, lettered, in order. Sub-tasks share the ticket's branch, **one commit each**, all in one pull
request, and **the order is the order.** There is no `feature/T-65a-...`.

**The layers are the frontend's, not the backend's:** data, then component, then validation, then errors,
then the route body, then language and tokens. Same principle — nothing is demonstrable until `e`.

|       | Layer               | Deliverable                                                                                  | Tests in the same commit                 | Proves                                                                                                        |
| ----- | ------------------- | -------------------------------------------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **a** | Data                | The `staff` container holding both resources and the save call, through the generated client | `practice-data.spec.ts`                  | Both calls issue once, no `org_id` is sent, and the 403 on `getSubscription` is a state rather than a failure |
| **b** | Component           | The presentational body, the counter, the read-only figures, every state in §4               | `practice-section.spec.ts`               | Criteria 1–4, and that nothing is computed client-side. **Not 5** — deferred, §5                              |
| **c** | Validation          | The name control, non-blank, and the disabled-while-unchanged rule                           | Same spec                                | Criteria 7, 8                                                                                                 |
| **d** | Errors              | `EPM-ORG-007` and `EPM-REQ-001` mapped through `ErrorMessage`, plus the unknown-code path    | Same spec                                | Criteria 9–12                                                                                                 |
| **e** | Route body          | The placeholder replaced. **The route itself is not touched**                                | Build chunk assertion                    | Criteria 16, and every remaining criterion                                                                    |
| **f** | Language and tokens | Translation keys, Arabic placeholders, colour pairs in the contrast test                     | `contrast.test.js`, manual Arabic render | Criteria 13–15                                                                                                |

### Why this order

**`a` first.** The 403 on `getSubscription` is a data-layer decision — treated as a failure there, every
layer above renders an error to every doctor.

**`c` and `d` before `e`.** Replacing the placeholder first ships a form with no validation and codes
rendered raw.

_Rejected: data, component, route, then validation, errors, language._

**`f` last**, because the token set is decided by what the component actually renders.

### What is not a sub-task

| Not                | Why             |
| ------------------ | --------------- |
| The route          | `T-97` wired it |
| `PageHeader`       | `T-98`          |
| Any backend change | None is needed  |

### The risk this shape carries

**Nothing is demonstrable until `e`**, and **criterion 16 is invisible to the suite** — only the build
catches an eager import. Run `npm run build` at `e`, not at the end.
