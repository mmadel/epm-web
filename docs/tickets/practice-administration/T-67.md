An org admin sees every colleague with their roles and branches, hires one, corrects one, and retires one

## 5. Logic

**Frontend.**

**The seat counter comes from `listStaff`'s response**, which carries `seatLimit` and `seatsUsed`
(`T-46` §4). **It is not counted from the rendered rows** — inactive rows are in the list and do not use a
seat, so counting them is wrong in exactly the case that matters.

**The counter is visible on the list, not only when adding.** A practice should see the limit approaching
rather than discover it at the moment of failure (`LLD-PRACTICE.md` §2.3).

**`EPM-ORG-006`'s message names both numbers from the response** and offers add-a-seat or change-plan,
both described as a conversation with the platform — there is no self-service route (`LLD-PRACTICE.md`
§2.5).

**Speciality is a select over reference data, not free text.** It is a row in a table, and a free-text
field guarantees `EPM-ORG-005` on a typo.

**Roles render read-only until `T-68`.** A second roles control here would be a second implementation of
the same call.

**After any successful write the list refetches**, so the counter moves with it.

**Inactive staff are dimmed, never hidden.**

**No `org_id` is sent, ever.**

## 7. Acceptance criteria

1. Given an org admin visits the route, then `listStaff` is called once and every staff member renders.
2. Given one active and one inactive staff member, then both render and the inactive one is dimmed.
3. Given six active and one inactive staff member on a plan of 20, then the counter reads 6 of 20 **from the response**, not from the row count.
4. Given the list in flight, then skeleton rows render and no control is interactive.
5. Given a doctor, when `listStaff` returns 403, then one message renders — not a blank screen and not a repeated call.
6. Given an org admin hires someone, then `createStaff` is called once, the list refetches, and the counter increases.
7. Given a write in flight, then its control is disabled and re-clicking sends nothing.
8. Given 409 `EPM-ORG-003`, then the message renders beneath the email field.
9. Given 422 `EPM-ORG-005`, then the message renders beneath the speciality field.
10. Given 422 `EPM-ORG-006`, then the message names both `limit` and `seatsUsed` from the response and offers both options.
11. Given 422 `EPM-ORG-010`, then the message renders on the retire confirmation and the row is unchanged.
12. Given the correct form, then it carries `Full name` and `Email` only — no roles, branches, speciality or status control.
13. Given the speciality control, then it is a select over reference data, not a free-text input.
14. Given the roles column, then it is read-only and no control calls `replaceStaffRoles`.
15. Given a retire confirmation, then it states the history is kept, and no string contains _delete_.
16. Given an unknown error code, then a generic message renders and the code is logged.
17. Given Arabic, then the layout mirrors with no second stylesheet and no `left`/`right`.
18. Given the section's styles, then no raw hex outside `_tokens.scss`.
19. Given every new colour pair, then it is in `contrast.test.js` and passes.
20. Given the built bundle, then `staff-section` is **not** in the initial chunk.
21. Given `ui`, then it does not import `api-client` as a value.
22. Given no request from this screen, then none carries an `org_id`, and none carries a password, token or invitation field.
23. `npm run build` and `ng test` green.

## 11. Sub-tasks

Six, lettered, in order. Sub-tasks share the ticket's branch, **one commit each**, all in one pull
request, and **the order is the order.** There is no `feature/T-67a-...`.

|       | Layer               | Deliverable                                                                                                                            | Tests in the same commit                                          | Proves                                                                                      |

| **b** | Component           | The list, dimmed inactive rows, the counter **read from the response**, read-only roles, the hire and correct forms, every state       | `staff-section.spec.ts`, `staff-counter.spec.ts`                  | Criteria 1–5, 12–14                                                                         |

| **d** | Errors              | `EPM-ORG-003`, `005`, `006`, `010` through `ErrorMessage`, with `006` reading both numbers from the response and offering both options | Same spec                                                         | Criteria 8–11, 16                                                                           |
| **e** | Route body          | The placeholder replaced. **The route itself is not touched**                                                                          | Build chunk assertion                                             | Criterion 20, and every remaining criterion                                                 |
| **f** | Language and tokens | Translation keys, Arabic placeholders, the _delete_-word assertion, colour pairs                                                       | `staff-strings.spec.ts`, `contrast.test.js`, manual Arabic render | Criteria 15, 17–19                                                                          |

### Why this order

**`a` first**, and the 403 handling is decided there. Treated as a failure, every layer above retries it.

**`b` carries the counter defect** — the single likeliest thing to ship wrong on this screen.

**`c` and `d` before `e`.** Replacing the placeholder first ships forms with no validation.

_Rejected: data, component, route, then validation, errors, language._

**`f` last.**
