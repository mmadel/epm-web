## 5. Logic

**Frontend.**

**Server data comes through the resource API, held in signals.** After any successful write, the list is
refetched rather than patched in place — a locally patched list and a server count disagree the first
time a write partly fails.

**`EPM-ORG-008`'s message names both numbers**, taken from the response's `limit` and `branchesUsed`
fields. **Neither is computed here** (`LLD.md` §7 — the server sends facts, the client owns the wording).

**Inactive branches are dimmed, never hidden.** Hiding them makes staff think data was lost
(`LLD-PRACTICE.md` §2.2).

**The retire confirmation says the history is kept**, and the word _delete_ does not appear in any string
this ticket adds.

**Hiding write controls from a non-admin is presentation.** The server refuses regardless (`LLD.md` §12).

**No `org_id` is sent, ever.**

## 7. Acceptance criteria

1. Given the route is visited, then `listClinics` is called once and every branch renders.
2. Given one active and one inactive branch, then both render and the inactive one is visually dimmed, not absent.
3. Given the list in flight, then skeleton rows render and no control is interactive.
4. Given a doctor, then the list renders and no add, edit or retire control is present.
5. Given an org admin adds a branch, then `createClinic` is called once and the list refetches.
6. Given a write in flight, then its control is disabled and re-clicking sends nothing.
7. Given 409 `EPM-ORG-002`, then the message renders beneath the name field.
8. Given 422 `EPM-ORG-008`, then the message names both `limit` and `branchesUsed` **from the response**, not from a client count.
9. Given 422 `EPM-ORG-009`, then the message renders on the retire confirmation and the row is unchanged.
10. Given the retire confirmation, then it states the history is kept.
11. Given every string this ticket adds, then none contains the word _delete_ in either language.
12. Given 404 on a write, then the list refetches.
13. Given an unknown error code, then a generic message renders and the code is logged.
14. Given `listClinics` fails, then `ErrorMessage` renders with a working retry.
15. Given Arabic, then the layout mirrors with no second stylesheet and no `left`/`right`.
16. Given the section's styles, then no raw hex outside `_tokens.scss`.
17. Given every new colour pair, then it is in `contrast.test.js` and passes.
18. Given the built bundle, then `clinics-section` is **not** in the initial chunk.
19. Given `ui`, then it does not import `api-client` as a value.
20. Given no request from this screen, then none carries an `org_id`.
21. `npm run build` and `ng test` green.

## 11. Sub-tasks

Six, lettered, in order. Sub-tasks share the ticket's branch, **one commit each**, all in one pull
request, and **the order is the order.** There is no `feature/T-66a-...`.

|       | Layer               | Deliverable                                                                                           | Tests in the same commit                                            | Proves                                                                                       |
| ----- | ------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **a** | Data                | The `staff` container holding the list resource and the three writes, with refetch-after-write        | `clinics-data.spec.ts`                                              | Each call issues once, no `org_id` is sent, and the list refetches rather than being patched |
| **b** | Component           | The list, dimmed inactive rows, the add and edit forms, the retire confirmation, every state in §4    | `clinics-section.spec.ts`                                           | Criteria 1–4                                                                                 |
| **c** | Validation          | The name control, non-blank, and disabled-while-in-flight                                             | Same spec                                                           | Criteria 6                                                                                   |
| **d** | Errors              | `EPM-ORG-002`, `008`, `009` through `ErrorMessage`, with `008` reading both numbers from the response | Same spec                                                           | Criteria 7–9, 13                                                                             |
| **e** | Route body          | The placeholder replaced. **The route itself is not touched**                                         | Build chunk assertion                                               | Criterion 18, and every remaining criterion                                                  |
| **f** | Language and tokens | Translation keys, Arabic placeholders, the _delete_-word assertion, colour pairs                      | `clinics-strings.spec.ts`, `contrast.test.js`, manual Arabic render | Criteria 11, 15–17                                                                           |

### Why this order

**`a` first**, and refetch-after-write is decided there. A patched list passes every fixture-based spec.

**`d` carries the ticket's likeliest defect** — reading `limit` and `branchesUsed` from the response
rather than from a local count.

**`c` and `d` before `e`.** Replacing the placeholder first ships a form with no validation.

_Rejected: data, component, route, then validation, errors, language._

**`f` last**, though the _delete_-word assertion belongs there rather than earlier because it runs over the
finished string files.
