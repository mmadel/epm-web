## 2. Goal

The pulse glyph is drawn in one place, so changing it changes it everywhere.

---

## 3. Scope

### In

- The platform console moved onto `ui`'s `lib-wordmark`
- Its own glyph and header markup deleted
- A visual comparison recorded before and after, so a silent regression is caught

### Out

- **Redrawing the glyph.** Whichever of the two is correct is chosen and the other deleted — §10
- Any change to the staff console. It already uses `lib-wordmark`
- Rebranding of any kind

---

## 4. Contract

**Frontend.** `None.` No new component, no route, no screen.

**The platform console renders `lib-wordmark`**, and no glyph markup remains in `platform`.

**This ticket must produce no functional diff** — only one implementation where there were two.

---

## 5. Logic

**Frontend.**

**One of the two drawings is chosen; the other is deleted.** They differ today or they would not both
exist. **Which one is right is a design answer, not an implementer's** — §10.

**Nothing about `lib-wordmark`'s inputs changes.** If `platform` needs something `lib-wordmark` does not
offer, that is a finding, not an input to add — §10.

**The glyph carries no text.** Whatever accessible name the platform header uses stays with the header,
not the glyph, so `T-98`'s `PageHeader` and this ticket do not both own it.

---

## 6. Data

`No table created, altered or dropped. No migration.` No server call.

## 7. Acceptance criteria

1. Given the platform console's header, then it renders `lib-wordmark`.
2. Given `projects/platform/`, then no glyph markup, path data or SVG for the pulse remains.
3. Given the staff console, then it renders unchanged.
4. Given both consoles, then the glyph is visually identical in each.
5. Given the glyph's accessible name in `platform`, then it is unchanged from before this ticket.
6. Given `dir="rtl"`, then the glyph renders correctly in both consoles.
7. Given the colour tokens, then no raw hex was introduced.
8. `npm run build` and `ng test` green.

## 11. Sub-tasks

Three, lettered, in order. Sub-tasks share the ticket's branch, **one commit each**, all in one pull
request, and **the order is the order.** There is no `feature/T-100a-...`.

|       | Layer        | Deliverable                                                                                        | Tests in the same commit               | Proves                                                                  |
| ----- | ------------ | -------------------------------------------------------------------------------------------------- | -------------------------------------- | ----------------------------------------------------------------------- |
| **a** | Comparison   | Both glyphs rendered side by side, the difference recorded, the winner named in the commit message | —                                      | The choice was made deliberately, not by whichever file was edited last |
| **b** | Adoption     | `platform` rendering `lib-wordmark`, its own markup deleted                                        | `platform` header spec, grep assertion | Criteria 1, 2, 5                                                        |
| **c** | Verification | Both consoles, both directions, screenshots                                                        | Manual, recorded                       | Criteria 3, 4, 6                                                        |

### Why this order

**`a` first**, because it is the only part that is a decision. Doing it after adoption means the choice was
made by accident.

**`c` separate from `b`**, because a grep proves deletion and only a person proves the two consoles still
look the same.

### The risk this shape carries

**Nothing here is caught by the suite except deletion.** The real risk is a silent visual regression in a
console nobody on this ticket is looking at — which is why `c` requires screenshots of **both**.
