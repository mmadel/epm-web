## 2. Goal

A platform admin opens the console, signs in against Keycloak, and reaches a real API route as
themselves. Signing out puts them back at the login screen.

**Frontend only, and nothing blocks it.** The Angular dev proxy forwards `/api` to `:8080`
server-side, so the browser sees a single origin and no CORS is involved. **T-112 is deferred** —
it returns at deployment, when `ng serve` is no longer in the path. **All fourteen criteria are
reachable today.**

## 3. Scope

- **In** — OIDC wiring in the `core` library, configured per app. Both consoles signing in. An HTTP
  interceptor attaching the token to generated `api-client` calls. A route guard. Sign-out. The
  library decision recorded in `DECISIONS.md`.
- **Out** — CORS (**T-112**, deferred). Creating accounts (`LLD-IDENTITY.md` §6, undesigned). How a new
  account gets its first password (`LLD-INFRASTRUCTURE.md` §I25 item 1, undesigned). Enabling the
  `orgFilter`. Anything in the patient app — `patient-app` is a placeholder and Part 4 has no design.
  Role-based hiding of navigation: roles come from the API's principal, not the token, and no route
  here depends on one.

## 4. Contract

No API route. The contract is what the consoles do.

| | |
|---|---|
| Route | `/` when signed out redirects to Keycloak. The return URL is honoured after sign-in |
| Guard | Every section route is behind it. An unauthenticated visit never renders a shell |
| Flow | Authorization code with **PKCE `S256`**. Public client, no secret |
| Client id | `platform-console` on `epm-platform` · `staff-console` on `epm-staff` |
| Sign-out | Ends the Keycloak session and returns to the post-logout URI, not just the local one |

**States, each with something visible:**

| State | Trigger | User sees |
|---|---|---|
| Redirecting | App start, no session | A neutral splash. **Never a flash of the signed-in shell** |
| Signing in | Return from Keycloak, code exchange in flight | Loading |
| Signed in | Token acquired, first API call succeeded | The shell |
| Recognised but not permitted | API answers 403 | A plain "your account is not set up for this console" page. **Not a login loop** |
| Provider unreachable | Keycloak down | An error page naming the provider. Not a blank screen |
| Signed out | Explicit sign-out, or refresh failed | Back to the login redirect |

**The 403 state is the one that gets missed.** A valid token whose `sub` matches no row is
`LLD-IDENTITY.md` §4's case, and a console that retries the login on a 403 spins forever.

## 5. Logic

OIDC configuration lives in `core`; each app supplies its own issuer and client id. **`ui` must not
import `api-client`**, and this ticket does not change that.

1. On start, restore a session if one exists. Otherwise redirect to Keycloak.
2. On return, exchange the code and store the token.
3. The interceptor attaches `Authorization: Bearer` **only to requests to the API's base URL** —
   which through the dev proxy is the relative path **`/api/...`**, never an absolute
   `http://localhost:8080`. An absolute URL bypasses the proxy, hits CORS immediately, and hardcodes
   a development address into the bundle. Attaching the header to every outbound request leaks the
   token to anything the app talks to.
4. Refresh silently before expiry. Refresh failure signs the user out — it does not retry forever.
5. 401 from the API → sign out and redirect. 403 → the not-permitted page, **no retry**.

**Nothing decodes the token to make a decision.** Not roles, not `org_id`, not the practice. Claims
are not read for logic — `LLD-INFRASTRUCTURE.md` §I9. What the user may do comes from the API.

### Configuration per app

| | `platform` | `staff` |
|---|---|---|
| Issuer | `http://localhost:8180/realms/epm-platform` | `.../realms/epm-staff` |
| Client id | `platform-console` | `staff-console` |
| Redirect | `http://localhost:4400` | `http://localhost:4200` |

**The issuer string must match `.well-known` character for character.** A mismatch produces tokens
that verify and are refused anyway — `LLD-INFRASTRUCTURE.md` §I5.

## 10. Stop and report

| Situation | Do not |
|---|---|
| Tempted to read a role, `org_id` or a practice id out of the token to decide what to render | **Stop.** §I9. The API's principal is the source |
| Tempted to attach the token to all outbound requests because the interceptor is fiddly | Stop. Criterion 4 |
| Tempted to enable direct access grants so the console can post a username and password | Stop. The console must never handle a password — §I8 |
| A 403 makes the app retry the login | Stop. Criterion 10, and the failure this ticket exists to catch |
| The issuer in the app config differs from `.well-known` by a character | Stop. §I5 |
| Tempted to store the token in `localStorage` because refresh is awkward | Stop and report what is awkward |
| Tempted to add a second OIDC library because the first is fighting you | Stop and report. Two auth libraries in one workspace is a permanent tax |
| A call to `/api` fails with a CORS error | The interceptor is using an absolute URL and bypassing the proxy. **Fix the URL, do not add CORS** — that is T-112 and it is deferred |
| Tempted to hardcode `http://localhost:8080` anywhere | Stop. It bypasses the proxy and ships a development URL in the bundle |

## The library choice

`LLD-main.md` §T6 names no OIDC library and this ticket needs one.

**Take `angular-auth-oidc-client`.** Standalone-component native, does PKCE and silent renew without
a wrapper, and has no dependency on Keycloak specifically — which matters because the provider is a
decision this product has already reconsidered once.

*Rejected: `keycloak-angular` with `keycloak-js`.* The obvious choice, and it binds the console to
Keycloak's own client library, which split from the server at 26.2 and now follows its own release
cadence — a second version to track against a server the product may not keep.

*Rejected: hand-rolling the code exchange.* PKCE, silent renew, storage and clock skew are four
places to be subtly wrong, and being subtly wrong in auth looks like working.

**Record it in `DECISIONS.md` as part of this ticket.** Adding a library is a decision, not an
implementation detail.
