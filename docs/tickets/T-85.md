## 2. Goal

Every request the Angular apps make is typed from the backend's own specification, so a change to a
field name breaks the build instead of reaching a user.

## 3. Scope

**In**

- openapi-generator wired into the `epm-web` workspace, reading `openapi/openapi.json` from `T-84`
- The generated client emitted into the `api-client` library under `projects/`
- An npm script that regenerates it, and a CI step that fails if the committed output is stale
- `.gitignore` and lint configuration so generated files are not hand-edited or reformatted

**Out**

- Any screen. The first consumer is `T-64`
- Any hand-written wrapper, facade or service around the generated methods. Screens call the generated methods directly
- Authentication headers on requests — `T-80`
- Generating clients for anything but this API

**Nothing in this ticket renders.** It is finished when a screen _could_ call `onboardOrganization`
with full type checking, not when one does.

## 4. Contract

|                 |                                                              |
| --------------- | ------------------------------------------------------------ |
| Input           | `openapi/openapi.json`, committed by `T-84`                  |
| Output          | Generated TypeScript in `projects/api-client/src/generated/` |
| Regenerate with | `npm run generate:api`                                       |
| Consumed by     | `staff` and `patient` apps, by importing from `api-client`   |

The generated client must expose one method per `operationId`. Today that is
`onboardOrganization(body)`, returning the typed 201 and 200 bodies.

**No interface in the workspace may mirror a server request or response.** If a type is needed, it
comes from `api-client`.

## 5. Logic

`None.` No component, no state, no derived value. This ticket produces code, not behaviour.

## 6. Data

`No table created, altered or dropped. No migration.` No browser storage of any kind.

## 7. Acceptance criteria

1. Given a clean checkout, when `npm run generate:api` runs, then the client is produced into `projects/api-client/src/generated/`.
2. Given the generated client, when a file imports `onboardOrganization` and passes a correctly shaped body, then `ng build` succeeds.
3. Given the generated client, when a file passes a body with a field name that does not exist in the specification, then `ng build` **fails**, naming that field.
4. Given `openapi/openapi.json` changes and the client is not regenerated, when CI runs, then it fails naming the difference.
5. Given the generated client, then the request type for `onboardOrganization` requires `name`, `plan`, `clinics` and `staff`, and permits no server-set field — no id, no `status`, no `seatLimit`, no timestamp.
6. Given the generated client, then the 201 and 200 response types both carry `organizationId`, `subscriptionId`, `clinics` and `staff`.
7. Given the generated client, then the error type carries `code`, and `code` is required.
8. Given the workspace, when it is searched, then no hand-written interface duplicates a generated request or response type.
9. Given a generated file, then it is excluded from lint and formatting rules — a reformatted generated file would differ from its own regeneration.

## 8. Tests

| Kind             | What it proves                                                              | Where                                            |
| ---------------- | --------------------------------------------------------------------------- | ------------------------------------------------ |
| Compile check    | Criteria 2 and 3 — a wrong field name is a build failure, not a runtime one | A `.spec.ts` type-assertion file in `api-client` |
| CI step          | Criterion 4 — regenerate, `git diff --exit-code`                            | Workflow                                         |
| Repository check | Criterion 8 — no hand-written mirrors                                       | Lint rule or a grep step in CI                   |

**What fails without the change:** all of them. Nothing generates a client today.

Criterion 3 is the one to prove deliberately: write a line with a misspelled field, watch `ng build`
go red, delete it. That failure is the entire value of this ticket.

## 9. Definition of done

- [ ] All 9 acceptance criteria demonstrably met
- [ ] Tests from §8 exist and fail without the change
- [ ] `ng build` and `ng test` green for both apps
- [ ] Generated output committed, and CI fails when it is stale
- [ ] The PR description shows the build failing on a misspelled field, then passing
- [ ] One commit, branch pushed, PR opened with this list ticked

## 10. Stop and report

| Situation                                                                | Do not                                                                                                                                                                         |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `openapi/openapi.json` does not exist                                    | Hand-write the types, or write the spec yourself. `T-84` owns it — report that it is not done                                                                                  |
| The generated client will not compile against the pinned Angular version | Hand-edit the generated output. Report it — the generator version or its template is the fix                                                                                   |
| A generated type disagrees with `LLD-ORGANIZATION.md` §2.1               | Correct the generated file. The spec comes from the controllers, and `LLD.md` says where the code disagrees with the design, one of them is wrong — report which fields differ |
| A screen is needed to prove the client works                             | Build a screen. A type-assertion file is the proof. `T-64` is the first screen                                                                                                 |
